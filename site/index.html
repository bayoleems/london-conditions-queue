Why predict this?

The problem

Planning permission usually comes with conditions: drainage, construction logistics, materials. Many must be signed off before work can start. Councils have 8 weeks to decide each sign-off, and more than half take longer. The delay comes after the scheme has already been approved, so it holds up homes that are otherwise ready to go.

Who the prediction helps

Councils can flag high-risk sign-offs on the day they arrive and give them early officer time. Developers can plan start dates around a realistic sign-off date rather than the statutory one. Policy teams can see which features of an application, such as bundling many conditions, are linked to delay.

What counts as useful

The bar is the borough average: knowing only which council decides already tells you something. A model is worth using if it sorts applications into clearly higher- and lower-risk groups than that. It won't be right about every application, so it suits triage and planning ranges, not promises.

How long will it take?

Exact days can't be predicted much better than each borough's median, because most decisions land close to the 8-week deadline. The useful outputs are the order of applications, from quickest to slowest, and a "plan for" range.

What is being predicted

Target
days: days from submission (start_date) to decision (decided_date).
Still undecided
Days so far, up to when the data was fetched, marked as not yet decided. The survival model treats these as "at least this long".
Models
Ridge and LightGBM predict log(1 + days); the Cox survival model predicts the daily chance of a decision; the quantile models give P50 (typical) and P90 (plan for).
Tested on
2024–25 decisions, trained on 2021–23.

Reading the descriptions with JEV

A description has two parts: the request ("condition 13 (construction method statement)") and a copy of the original permission. The keyword tagger reads both, so it often tags the scheme. Jev, TypeSafe's decision model on OpenRouter, answers yes/no and multiple-choice questions about only the conditions requested. It labelled — of the modelled applications.

Definitions, method and what's left out
Late
Decided more than 56 days (8 weeks) after submission, or still undecided past that point when the data was fetched in August 2026.
AUC
How well a model ranks applications from most to least likely to be late. 0.5 is a coin flip, 1 is perfect.
C-index
The share of application pairs a model puts in the right order of time taken. Undecided applications count as "at least this long".
P50 and P90
Quantile predictions: the typical time, and the time by which about nine in ten should be decided.
Speed ratio
From the Cox survival model: how much a feature changes the daily chance of getting a decision. Below 1 is slower.
Keyword features
Topics, number of conditions and pre-start flag found by keyword matching on the whole description (conditions_queue.analysis).
JEV features
The same, labelled by Jev (~typesafe/jev-latest, OpenRouter's decisions API) from the request part only: a probability per topic, kept at 0.5 or more (conditions_queue.classify_jev).
Importance
Permutation importance: the drop in each model's test score when a feature is shuffled, as a share of all drops.

What's left out

Causes
These are associations. Applicants who bundle may differ in ways the data doesn't record.
Case detail
Consultee responses, extensions of time and validation dates aren't in the data and are likely the biggest missing drivers.
Application size
The app_size column: PlanIt's Small/Medium/Large label. It tracks the size of the scheme (Large: median 135 homes, Medium: 22, Small: 7) and is the strongest single predictor. Exactly how PlanIt assigns it hasn't been confirmed from its documentation.
Flood zones
Not tested: the national file is 2.5 GB.

Data: PlanIt-derived extract of London planning applications, discharge-of-condition applications submitted 2021–2025. Description labels by Jev (TypeSafe) via OpenRouter. External data from planning.data.gov.uk and the GLA's house price per square metre dataset.
